# 电子书重命名

把一堆文件名乱七八糟的电子书，按书里**内嵌的元数据**统一改成 `书名(作者).扩展名`。文件名里常见的副标题、内容简介、丛书名、版本说明、`z-library.sk` / `1lib.sk` / `tg@…` 这类站点广告，全部丢掉。

## 最重要的纪律：先看方案，再动手

改名是**不可逆**的破坏性操作，而且元数据经常出人意料（有的书 `dc:title` 里就带着广告，有的作者字段是一串助手名单）。所以：

1. **永远先跑 dry-run**（脚本默认就是 dry-run），把「原文件名 → 新文件名」对照表**完整打印给用户**。
2. **等用户确认**。把存疑的行标出来（例如某本书截掉副标题后信息量骤减、某本书作者是一串名字），主动请用户拍板。
3. 用户确认后才加 `--apply` 执行，然后**再跑一次 dry-run 验证**——此时应该显示「待改名 0 个」，说明结果稳定、可重复执行。

不要在用户没确认时直接 `--apply`。如果用户在一句话里就说了「直接改不用问我」，那属于已授权的例外，可以执行，但仍要打印对照表。

## 流程

### 第 1 步：定位电子书

常见位置：`~/download`、`~/storage/downloads`（= `/storage/emulated/0/Download`）。先 `ls` 看看有哪些书、什么格式。只处理 `.epub / .mobi / .azw3 / .azw`；**PDF、TXT 等不处理**（PDF 的元数据普遍是水印或乱码，见 `references/filename-rules.md`）。

### 第 2 步：dry-run

```bash
python3 <skill-dir>/scripts/rename_ebooks.py <目录>            # 只看方案
```

脚本直接读文件内部元数据，不依赖 Calibre：

- `.epub` → `content.opf` 里的 `dc:title` / `dc:creator`
- `.mobi/.azw3` → MOBI 头的 EXTH 记录（`100`=作者，`503`=标题）

### 第 3 步：人工确认

把对照表给用户看，并说明：

- 脚本会**自动跳过**目标重名、目标已存在、元数据无书名的文件，绝不覆盖；
- 有疑问的书名/作者，可以用 `--overrides` 逐条修正（见下）；
- 分卷（`第2卷`/`卷02`）会被保留，避免同系列重名。

### 第 4 步：执行

```bash
python3 <skill-dir>/scripts/rename_ebooks.py <目录> --apply
```

### 第 5 步：验证

```bash
python3 <skill-dir>/scripts/rename_ebooks.py <目录>
```

输出「待改名 0 个」即成功。若有残留，说明清洗规则没覆盖到，回来调整规则或加 overrides。

## 命名规则速查

细节（正则、示例、为什么这么设计）见 `references/filename-rules.md`，要点：

| 项目 | 处理 |
| --- | --- |
| 副标题 | 在第一个 `：/:`、`—`、` - ` 处截断 |
| 简介/丛书/版本 | 从第一个 `（…）`/`(…)`/`【…】`/`[…]` 起整段丢弃 |
| 站点广告 | 去掉 `tg@…`、`t.me/…`、`z-library.*`、`1lib.*`、`annas-archive.*`、`libgen.*` 等 |
| 系列信息 | `·全13册（…）` 这类整段丢弃 |
| 分卷 | `第2卷`/`卷02`/`卷二` 保留，`卷01` 规范成 `第01卷` |
| 作者 | `•`→`·`，多作者统一用 `, `，去重 `陶涵 [陶涵]`→`陶涵` |
| 作者国别前缀 | **默认保留** `[美]`/`【韩】`/`（英）`；要删加 `--strip-author-prefix` |
| 文件名字符 | 替换 `/ \ : * ? " < > |`，中文全角标点（如 `：`）保留 |

## 用 --overrides 修正个别书

通用规则不可能对每本书都对（比如漫画 `FIREPUNCH炎拳 - 卷01` 想叫 `炎拳 第01卷`，或某本书冒号后面其实不是副标题）。这时不要改脚本，写一个修正表：

```json
[
  {"match": "^FIREPUNCH炎拳", "title": "炎拳 {volume}", "author": "藤本樹"},
  {"match": "^图解Skill：", "title": "{raw_title}"}
]
```

- 每条形如 `{"match": "<正则>", "title": "<模板>", "author": "<模板>"}`，按顺序匹配**原始 metadata 书名**，首个命中生效。
- 模板可用占位符 `{raw_title}`、`{raw_author}`、`{volume}`（`volume` 已规范化，如 `第01卷`；没有分卷时为空）。
- 只写 `title` 或只写 `author` 都可以，另一个继续走通用规则。
- 因为匹配的是 metadata 而不是文件名，**重复运行仍然幂等**，不会改一次名就失效。

模板见 `evals/fixtures/overrides.example.json`。

## 常见坑

- **别改完就删 overrides**：下次再跑同一批书还会用到；它匹配 metadata，长期有效。
- **不要用文件名反推书名**：文件名里往往只有副标题或丛书名（如 `1929年大崩盘 (华安基金世界资本经典译丛).epub`，括号里根本不是作者）。务必以元数据为准。
- **作者字段是助手名单**：日漫等作者字段常列一串协作者，通用规则会全部保留；想只留主作者就加 overrides。
- **同名备份文件**：`要有光（梁鸿）.bak.epub` 里的 `.bak` 会保留，变成 `要有光(梁鸿).bak.epub`，不会和正本撞名。
- **PDF 不建议处理**：实测 PDF 的 Title/Author 多为空或水印乱码；若用户坚持，只能依据现有文件名，且要说明不可靠。
